Funnels show those crashes, traces and slow network requests next to the step where users dropped off. You can also watch their session replays.

## Catch crashes in native code 💥

The Android SDK now reports native crashes on Android 12 and above. It captures crashes in your C or C++ code and in SDKs with native libraries. Every native crash comes with a session replay, just like your Java and Kotlin crashes.

Native crash reporting is off by default. Turn it on in the `measure` block of your app's `build.gradle.kts`:

```kotlin
measure {
  enableNativeCrashReporting = true
}
```

See the [native crash docs](/docs/error-monitoring#native-crashes-android) to set it up. To learn why native memory bugs crash with SIGSEGV and how to debug them, read our post on [SIGSEGV crashes on Android](/blog/sigsegv-crashes-android-gwp-asan).

## Catch app hangs on iOS 🧊

The iOS SDK reports a hang when the main thread stays blocked for at least 2 seconds. Each report includes the main thread's stack, the blocked duration and whether the app recovered or iOS killed it.

The Errors page groups hangs by where the main thread was blocked. Hang events also appear in session replay, in the app hang free sessions count on the overview page and in the daily email. Change the threshold and sampling from the dashboard without shipping a new build.

See [App hang reporting](/docs/error-monitoring#app-hang-reporting) for how detection works.

## Better grouping for ANRs 🔍

On Android 11 and above, the SDK now collects the full ART thread dump for each ANR. We use it to group ANRs by the code that blocked the main thread, including when the main thread is waiting on a lock held by another thread.

Read our post on [diagnosing ANRs in production](/blog/application-not-responding-android) for more on reading thread dumps.

The Android SDK also supports Android 17 triggers. Android can capture a heap dump when your app runs out of memory, a trace of a slow cold start or a trace when it kills your app for using too much CPU.

Read [Debug Android Performance in Production With Trigger-Based Profiling](/blog/android-trigger-based-profiling) to see how we use these traces.
